# **Пункт 3. Принятие решения**

**Выбранное решение — рекомендация выгодных АЗС**

Я предлагаю выделять наиболее выгодные по цене дизеля АЗС среди ближайших подходящих станций и показывать водителю потенциальную экономию.

### Описание решения в 10 строках

1. **Проблема:** водители выбирают дорогие АЗС и иногда расходуют весь доступный лимит за одну заправку.
2. **Цель:** снизить расходы перевозчика на топливо, не усложняя водителю выполнение рейса.
3. **Решение:** добавить в список АЗС рекомендацию «Выгодная заправка» для станции с наиболее низкой ценой дизеля среди ближайших подходящих вариантов.
4. **Интерфейс:** визуально выделять рекомендуемую станцию и показывать стоимость литра, расстояние и возможную экономию.
5. **Расчёт:** сравнивать стоимость одинакового объёма дизеля на рекомендуемой и более дорогой ближайшей подходящей АЗС.
6. **Ограничения:** учитывать наличие топлива и близость станции, чтобы экономия не требовала большого отклонения от маршрута.
7. **Свобода выбора:** не запрещать водителю выбирать другие АЗС, поскольку в рейсе могут возникать непредвиденные обстоятельства.
8. **Реализация:** использовать существующие методы `getStations()` и `getDriverLocation()`, добавив сортировку и расчёт экономии в `app.js`.
9. **Срок:** за две недели реализовать рекомендацию, обновить интерфейс, проверить работу при плохой связи и добавить сбор данных для оценки результата.
10. **Ожидаемый результат:** водители чаще выбирают более дешёвые станции, что снижает среднюю стоимость закупаемого топлива.

## Почему выбрано это решение

При ограничении в две недели и одного разработчика важно выбрать изменение с понятным эффектом и минимальной сложностью реализации.

В API уже имеются координаты АЗС, цены на топливо и местоположение водителя. Поэтому рекомендацию можно реализовать преимущественно на стороне приложения, без масштабного изменения серверной логики.

При этом решение учитывает реальные условия работы водителя: плохую связь, ограниченное время и необходимость быстро найти заправку. Оно не создаёт дополнительных обязательных действий и не блокирует покупку топлива.

Важно также разделять две проблемы. Использование всего лимита за одну заправку не обязательно означает неэффективные расходы: водитель может действительно нуждаться в большом объёме топлива для рейса. Поэтому сначала я предлагаю снижать стоимость покупки, а не ограничивать количество литров.

## Две отвергнутые альтернативы

| Альтернатива | Почему отказались |
|---|---|
| **Ограничить объём одной заправки**, например до 150 литров. | Не решает проблему высокой цены, так как водитель может оформить несколько заказов или чаще останавливаться. Это увеличит количество действий, что особенно неудобно при плохой связи. |
| **Запретить заправку на дорогих АЗС.** | Может оставить водителя без топлива на удалённом участке трассы. Потребуется механизм исключений и согласования с диспетчером, который сложно качественно реализовать за две недели. |

## Одна метрика для оценки через месяц

**Средняя фактическая цена одного литра дизеля (₽/л).**

Формула:

`Средняя цена = Общая сумма списаний за дизель / Фактически залитые литры`

Через месяц сравним среднюю цену литра у водителей с рекомендациями с сопоставимой контрольной группой без рекомендаций за тот же период. Это поможет учесть изменение рыночных цен и различия маршрутов.

**Критерий ошибки:** если средняя цена литра не снизится относительно контрольной группы, значит выбранная мера не дала ожидаемого результата.

## Итог

Я выбираю рекомендацию выгодных АЗС, потому что её можно реализовать за две недели силами одного разработчика, используя существующие данные API. Она помогает перевозчику снижать стоимость топлива, сохраняя свободу выбора водителя и не создавая рисков для выполнения рейса.

Через месяц решение оценивается по средней фактической цене литра дизеля. Если улучшения нет, решение следует пересмотреть.
